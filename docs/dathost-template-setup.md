# DatHost MatchZy Template: Office Club Competitive

## The chosen design

Use **one stopped, deletion-protected CS2 template** with Metamod, CounterStrikeSharp, and the pinned MatchZy 0.8.15 Linux bundle. The Office Club Competitive worker duplicates that template for each ready 10-player match, applies per-match secrets/settings while the duplicate is off, starts it, and loads an authenticated MatchZy JSON config over HTTPS.

This is deliberately the **custom MatchZy flow**, not DatHost's Match API. It is the correct fit for this module because the bot already owns captains, team drafting, map veto, MatchZy event ingestion, authenticated config delivery, and the Discord admin controls. Do not enable or create a DatHost `cs2-match` for an Office Club Competitive duplicate: two match controllers would compete for the same server.

The template never contains a static roster, join password, RCON password, webhook URL, webhook token, or a loaded match. Those are unique credentials generated by the worker for each disposable duplicate.

## Exact template specification

Create a CS2 server in the DatHost control panel with these durable settings:

| Setting             | Template value                                  | Why                                                                                                   |
| ------------------- | ----------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| Name                | `Office Club Competitive — MatchZy template`    | Clearly identifies the protected source.                                                              |
| Game                | CS2                                             | Required by the service.                                                                              |
| Slots               | `11`                                            | 5v5 plus one GOTV slot; the worker also applies the selected profile's slot count to every duplicate. |
| Game mode           | `custom`                                        | Prevents a stock public mode from defining the match. MatchZy owns the actual series rules.           |
| Metamod             | enabled                                         | Required host for CounterStrikeSharp/MatchZy.                                                         |
| GOTV                | enabled                                         | MatchZy demo recording needs `tv_enable 1`; the worker reasserts this on each duplicate.              |
| Private server      | enabled                                         | The worker sets a fresh join password per match.                                                      |
| Deletion protection | **enabled**                                     | Mandatory: the worker will never delete a protected template.                                         |
| Autostop            | enabled, 15 minutes                             | A second safety net for future duplicates; normal cleanup still deletes them.                         |
| GSLT                | leave blank unless your deployment requires one | DatHost does not copy a GSLT to duplicates, and this module does not provision one.                   |

The template location is not important: the worker passes the guild's configured region when duplicating. Select a normal official-map boot map (for example `de_mirage`); MatchZy changes to the vetoed map when it loads the match.

## Install the pinned runtime

1. In DatHost, enable Metamod on the template.
2. Download **`MatchZy-0.8.15-with-cssharp-linux.zip`** from the pinned MatchZy 0.8.15 release. Extract its contents into the server's `csgo/` directory through DatHost FTP/file upload. The resulting install must include MatchZy under `addons/counterstrikesharp/plugins` and `cfg/MatchZy`.
3. Start the template once and use the DatHost console to run:

   ```text
   meta list
   css_plugins list
   ```

   The first must show CounterStrikeSharp and the second must show MatchZy. Do not proceed on a partial install.

4. Edit `csgo/cfg/MatchZy/config.cfg` to add the following service-safe baseline (leave the package's warmup/knife/live config files otherwise intact):

   ```cfg
   // Office Club Competitive template baseline. Per-match values arrive via matchzy_loadmatch_url.
   matchzy_kick_when_no_match_loaded 1
   matchzy_whitelist_enabled_default 1
   matchzy_everyone_is_admin 0
   matchzy_reset_cvars_on_series_end 1
   matchzy_demo_path "MatchZy/"
   matchzy_demo_name_format "{TIME}_{MATCH_ID}_{MAP}_{TEAM1}_vs_{TEAM2}"
   ```

   The first two settings keep an unconfigured duplicate closed until the bot has loaded its exact SteamID64 roster. The bot's Discord-side controls use DatHost console access; they do not require granting players MatchZy admin rights.

5. Stop the template. After any plugin or configuration change, let the template run long enough for DatHost's duplicate cache to refresh, then stop it once (or use DatHost's file-sync endpoint) before testing a new duplicate.

## Configure the bot

Set the source template ID only—never an already-created match server ID:

```bash
DATHOST_EMAIL=your-dathost-login-email
DATHOST_PASSWORD=your-dathost-password
DATHOST_TEMPLATE_SERVER_ID=protected-template-server-id
PUBLIC_BASE_URL=https://competitive.example.com
```

Use `/match config configure` to select that same template and a valid DatHost location for each guild. Then use `/match admin diagnostics` before creating a real match. The bot checks template accessibility there without mutating it.

## What the worker changes on every duplicate

The source stays untouched. Before booting a copy, the worker sets its name and ownership marker, region, profile slot count, GOTV/private-server flags, unique RCON password, unique join password, autostop, and disables deletion protection. Once booted, it waits for a fresh single-server status response and sends only:

```text
matchzy_loadmatch_url "https://competitive.example.com/internal/matches/<id>/matchzy-config" "x-matchzy-token" "<short-lived-token>"
```

That config supplies the selected map, exact SteamID64 team lists, readiness threshold, side policy, allowed CVARs, and unique event webhook token. It is intentionally not stored on the template.

## Acceptance checklist

- The template itself has deletion protection on and remains stopped after validation.
- `meta list` reports CounterStrikeSharp and `css_plugins list` reports MatchZy 0.8.15.
- A disposable duplicate has a different ID, the guild-selected location, 11 slots for `competitive_5v5`, private-server/GOTV enabled, and a unique `tenman:<matchId>:<attemptId>` marker.
- Before configuration load, an unrostered player cannot enter; after load, each of the ten assigned SteamID64s can join and reaches the correct team.
- The ready-up threshold is 10 for `competitive_5v5`; the knife round occurs unless that profile disables it.
- `series_start`, `going_live`, `round_end`, `map_result`, and `series_end` reach the bot with the per-match `x-matchzy-token`.
- A MatchZy demo is present before cleanup when demo retention is enabled; collect it before deletion because DatHost deletes server files with the duplicate.
- End, failed load, and canceled-match paths delete only the owned duplicate. Confirm the protected template ID is never modified or deleted.

## Operational prohibitions

- Do not add a static `whitelist.cfg`, permanent MatchZy admin IDs, RCON password, or webhook token to this shared template.
- Do not use DatHost's Match API on a MatchZy-controlled duplicate.
- Do not manually retry a timed-out duplicate request. Let the worker reconcile using its persisted marker/name/window evidence.
- Do not promote this document's checklist to staging evidence. It requires an actual authorized DatHost template and end-to-end test with the public HTTPS callback reachable from the game server.
